## 一、项目结构（Structure）

### 总体评价

技术栈现代且选型合理：Tauri 2（Rust 后端）+ Next.js 15（React 19 / TypeScript / Turbopack）+ TipTap 3 编辑器 + Zustand 5 状态管理 + shadcn/ui + Tailwind CSS 4 + SQLite（tauri-plugin-sql）。项目基于 codexu/note-gen 二次开发，会议模块（长录音、结构化纪要）为自研增强部分。

### 问题清单

| 编号 | 严重度 | 问题 | 位置 |
|------|--------|------|------|
| S1 | 🟡 | 依赖版本管理松散：存在未锁定的版本范围、部分类型包与运行时包版本不匹配 | `package.json` |
| S2 | 🟡 | 转写引擎代码重复：SenseVoice 与 Qwen3 两套转写逻辑大量复制粘贴，缺少公共抽象 | `src/app/core/main/meeting/meeting-transcribe.ts`、`meeting-transcribe-qwen3.ts` |
| S3 | 🟡 | 同步 Provider 之间存在重复实现（GitHub / Gitee / WebDAV 等各自独立实现相似逻辑） | `src/lib/sync/` |
| S4 | 🟡 | "上帝 Store"：article store 承担约 8 类职责（文章、目录树、工作区、拖拽、锁定、排序等），耦合严重 | `src/stores/article.ts` |
| S5 | 🟡 | 反向依赖：底层 lib 反向引用上层页面模块，破坏分层 | `src/lib/` → `src/app/core/` |
| S6 | 🟢 | 部分目录命名与实际职责不符，新人上手成本高 | `src/app/core/main/` |
| S7 | 🟢 | 存在已安装但未使用的依赖，增大包体积 | `package.json` |

## 二、业务流程（Process）

### 核心流程梳理

```
访前（材料生成）→ 访中（录音 + 笔记 + 自动纪要）→ 访后（待办、财务分析、贷审会助手、知识库沉淀）
```

- **访前**：`visit-generate-manager.ts` 后台任务队列驱动多文档并行生成。
- **访中**：`meeting-audio-recorder.ts` 长录音 + 分段转写 + 结构化纪要。
- **访后**：`meeting-customer-export.ts` 一键导出（归档、向量化、待办提取）。

自动化程度较高是亮点，但可靠性链路存在以下缺口：

### 问题清单

| 编号 | 严重度 | 问题 | 位置 |
|------|--------|------|------|
| P1 | 🔴 | 访前生成任务完成检测脆弱：依赖文件 mtime 轮询 + `Error:` 字符串嗅探判断成败，误判风险高 | `visit-generate-manager.ts` L218-231 |
| P2 | 🔴 | 导出管线静默吞错：向量化失败、待办提取失败等 6 处仅 `console.warn`，用户无感知，数据丢失不可见 | `meeting-customer-export.ts` L205-207、L254 等 |
| P3 | 🟡 | 长任务无断点续传：生成/导出中途关闭应用后任务状态丢失，需整体重来 | `visit-generate-manager.ts` |
| P4 | 🟡 | 客户删除级联不完整：删除客户后关联的会议记录、向量索引、待办未完全清理，产生孤儿数据 | `src/db/customers.ts` |

## 三、功能完整性（Functionality）

### 问题清单

| 编号 | 严重度 | 问题 | 位置 / 说明 |
|------|--------|------|------|
| F1 | 🔴 | **录音无崩溃恢复**：音频 chunk 仅存内存（`audioChunks: Blob[]`），应用崩溃 = 整场会议录音丢失。这是全项目最高风险点 | `meeting-audio-recorder.ts` L36-43 |
| F2 | 🟡 | 待办无到期提醒：有截止日期字段但无任何通知机制 | 待办模块 |
| F3 | 🟡 | 全局搜索覆盖不全：会议纪要、客户资料未纳入搜索范围 | 搜索模块 |
| F4 | 🟡 | 转写结果不可编辑修正：识别错误无法在原文上更正，直接影响纪要质量 | 会议模块 |
| F5 | 🔴 | 知识库 TXT 文件不被索引：多处硬编码 `.endsWith('.md')` 判断，TXT 导入后检索完全失效 | `src/lib/rag.ts` L561、L615、L743、L1308、L1378 |

## 五、改进优先级清单

### 第一梯队 —— 数据安全（立即处理）

1. **录音 chunk 定期落盘 + 崩溃恢复探测**（对应 F1）🔴
2. **导出管线错误显式上报**：静默 warn 改为 UI 提示 + 失败重试入口（对应 P2）🔴
3. **修复知识库 TXT 索引**：抽象文件类型判断，支持 `.txt`（对应 F5）🔴
4. **生成任务完成检测重构**：改为显式任务状态回调，弃用 mtime + 字符串嗅探（对应 P1）🔴

### 第二梯队 —— 核心体验补全

5. 转写结果原文可编辑修正（F4）
6. 待办到期通知（F2，可用 Tauri notification 插件低成本实现）
7. 全局搜索纳入会议纪要与客户资料（F3）
8. 客户删除级联清理补全（P4）
9. 长任务断点续传 / 状态持久化（P3）

### 第三梯队 —— 可维护性

10. 抽象转写引擎公共层，消除双套复制（S2）
11. 拆分 article "上帝 Store"（S4）
12. 修复 lib → app 反向依赖（S5）
13. 同步 Provider 公共基类抽取（S3）
14. 锁定依赖版本、清理未用依赖（S1、S7）

### 第四梯队 —— UI 打磨

15. 硬编码颜色替换为主题令牌（U1）
16. 会议模块 i18n 补全（U2）
17. 客户详情页信息架构重组（U3）
18. 目录命名整理（S6）

## 六、结论

项目核心业务链路（访前-访中-访后）已完整闭环，自动化程度高，是明显优势。当前最大风险集中在**数据安全**：录音无落盘恢复（F1）与静默吞错（P2）可能造成用户不可挽回的数据丢失，建议优先解决第一梯队 4 项后，再推进体验与可维护性改进。
